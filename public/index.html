◈ Netlify Connector
1Easy start

Let Claude run your Netlify.

This site is an MCP server that wraps the Netlify API. Add its URL to Claude as a custom connector and you can read failed deploy logs, trigger builds, roll back a bad release and manage environment variables — from inside a conversation.

2Setup

  1. Create a Netlify access token

    In Netlify: User settings → Applications → Personal access tokens. The token carries your full Netlify permissions, so treat it like a password. It stays on the server and is never sent to Claude.

  2. Set two environment variables

    On this site, under Site configuration → Environment variables:

    NETLIFY_API_TOKEN = your Netlify personal access token MCP_SHARED_SECRET = a long random string (generate one below)

    Until both are set the endpoint answers every request with 503 — it fails closed rather than handing the token's reach to whoever finds the URL. Changes need a redeploy to reach the function.

  3. Build your connector URL

    The secret travels as the last path segment, because Claude's custom-connector form takes a URL and nothing else.

    Nothing here is sent anywhere or stored — the value lives in this page until you close it. Keep the URL private: anyone holding it has the same reach as your Netlify token.

  4. Add it in Claude

    Settings → Connectors → Add custom connector, paste the URL, save. Then run the handshake below, or just ask "which Netlify sites can you see?"

3Instant output

Test the connection.

Runs a real handshake against the endpoint — initialize then tools/list — exactly as Claude does on connect.

5Safety

Give it less, if you want.

All optional, all set the same way as the two required variables.

VariableEffect
NETLIFY_MCP_READ_ONLYtrue hides every write tool from Claude and refuses it if called anyway. Nothing can be built, rolled back or changed.
NETLIFY_MCP_SITESComma-separated site ids or names. Tools refuse any other site, and the raw API escape hatch switches off, since it would defeat the restriction.
NETLIFY_MCP_DEFAULT_SITESite used when a call omits one, so "trigger a build" works without naming it.
NETLIFY_MCP_ACCOUNTDefault team slug for environment-variable tools, when it can't be inferred from the site.

Secrets stay secret

Environment variable values are never returned unless a call explicitly asks, and values Netlify holds as secret are never returned at all.

Rotation is one edit

Change MCP_SHARED_SECRET and every URL handed out before now stops working immediately.

6When it breaks

Four things go wrong.

  • 503, "not configured". NETLIFY_API_TOKEN or MCP_SHARED_SECRET is missing, or the site hasn't redeployed since you set them.
  • 401. The secret in the URL doesn't match. Watch for a trailing slash or a truncated paste.
  • Connects but lists no tools. Netlify rejected the token. Ask Claude to call netlify_whoami; the error comes back verbatim.
  • "Not in this connector's allowlist". NETLIFY_MCP_SITES is set and doesn't include that site.
